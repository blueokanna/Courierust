# 示例

仓库里每个示例都能直接编译运行（`cargo run --example <名字>`），是上手最快的方式。

| 示例 | 演示内容 | 运行 |
|---|---|---|
| `hello` | 单文件跑通 h2c 客户端 + 服务器 | `cargo run --example hello` |
| `greeter` | gRPC 服务器 + 客户端：unary（原始字节 + 类型化）、错误状态 | `cargo run --example greeter` |
| `streaming` | 服务器流式返回 `Body::Channel`，客户端逐块消费 | `cargo run --example streaming` |
| `priority` | RFC 9218：高优先级流优先于低优先级积压调度 | `cargo run --example priority` |
| `redirects` | 自动跟随 302 跳转链（RFC 9110） | `cargo run --example redirects` |
| `fingerprint` | 打印 JA3 / JA4 / Chrome HTTP/2 指纹值 | `cargo run --example fingerprint` |
| `https` | HTTPS（TLS 1.3）端到端：自签名 Ed25519 身份、校验客户端、ALPN 上的 h2 + HTTP/1.1 | `cargo run --example https` |
| `protocol_core` | HPACK + h2 编解码在内存管道上运行（无 socket）+ 自带哈希 | `cargo run --example protocol_core` |
| `diag` | loopback h2 echo 诊断 | `cargo run --example diag` |

## hello

单文件：随机端口起服务器，然后用 HTTP/2 客户端 GET/POST。一切入门的起点。

## greeter

后台 gRPC 服务器带两个方法 + 客户端调用——原始字节 `call`、类型化 `call_unary`、以及客户端侧暴露 `grpc-status` 的错误路径。

## streaming

服务器返回 `Body::Channel`，生产者线程喂数据，客户端从 channel 接收端逐块消费。HTTP/1.1（chunked）与 HTTP/2 下都可用。

## priority

先发 32 个 `urgency=7` 请求，再发一个 `urgency=0` 请求。WUCS 调度器不能让低优先级积压饿死高优先级流——示例打印高优先级请求的完成耗时。

## redirects

`302 -> 302 -> 200` 两跳链，客户端透明跟随，最终响应直接返回。

## fingerprint

打印确切的 ClientHello 参数（`chrome_tls_profile`）、JA3 字符串/哈希、JA4 与 Chrome HTTP/2 SETTINGS 顺序——这些是喂给你自己的 TLS 层的值。

## https

用 `tests/certs/` 里的自签名 Ed25519 证书（DER）开一个 HTTPS 服务器，客户端以同一张证书为根做校验。TLS 之上同时服务 h2（ALPN）与 HTTP/1.1；客户端 GET/POST `https://` URL 并打印状态码与响应体。真实部署换成你自己的证书链 + 私钥。

## protocol_core

无 socket 的 `no_std` 核心：HPACK 编解码往返、在内存管道上驱动的 h2 `Connection`（任何实现 `io::Read`/`io::Write` 的类型都行）、零依赖 MD5/SHA-256。

## diag

loopback h2 echo，打印状态码与响应体——接真实端点前快速确认栈正常。
