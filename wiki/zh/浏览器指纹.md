# 浏览器指纹

在意机器流量的服务器会指纹 **TLS ClientHello**（JA3 / JA4）和 **HTTP/2 握手**（SETTINGS 取值与顺序、头字段排序）。Courierust 自带可供客户端/服务端使用的 TLS 1.3 实现；本模块提供指纹参数以及自带的 MD5/SHA-256。部署需要时，也可以把同一组参数交给外部 TLS 库。

## JA3

```rust
use courierust::courierust_fingerprint::{chrome_tls_profile, ja3_hash, ja3_string};

let profile = chrome_tls_profile(); // TlsProfile = ClientHello 参数
let s = ja3_string(&profile);       // "771,4865-4866-...,0-...,23,0-29-..."
let hash = ja3_hash(&profile);      // 32 位十六进制
```

Chrome profile 与公开记录在测试套件里做了对拍：

```rust
assert_eq!(ja3_hash(&profile), "cd08e31494f9531f560d64c695473da9");
```

## JA4

```rust
use courierust::courierust_fingerprint::ja4;

let f = ja4(&profile);
// 格式: t<版本>d<密码套件>h<扩展><alpn>_<SNI 哈希>_<密码套件哈希>
assert_eq!(f, "t13d1516h2_8daaf6152771_e5627efa2ab1");
```

GREASE 值会自动过滤（JA4 规范要求），所以 `chrome_tls_profile()` 产出的 JA4 是干净的。

## profile 对象

`TlsProfile` 是纯数据，可以自己构造：

```rust
use courierust::courierust_fingerprint::TlsProfile;

let custom = TlsProfile {
    tls_version: 0x0304, // TLS 1.3
    ciphers: vec![0x1301, 0x1302, 0x1303], // AES-128-GCM, AES-256-GCM, CHACHA
    extensions: vec![0x002b, 0x001d, 0x0000], // supported_versions, ..., SNI
    alpn: vec!["h2".into(), "http/1.1".into()],
    ..Default::default()
};
```

把这些值喂给你的 TLS 库的 ClientHello 构造器即可。

## Chrome HTTP/2 指纹

除了 TLS，Chrome 还靠 HTTP/2 行为识别。`ChromeH2Fingerprint` 承载了 Chromium 长期使用的默认值：

```rust
use courierust::courierust_fingerprint::h2::ChromeH2Fingerprint;

let fp = ChromeH2Fingerprint::chrome();

// 按 Chrome 发送顺序给出 SETTINGS 项：
let entries = fp.settings_entries(); // Vec<Setting>

// 应用到 Settings 对象，或直接产出一整套 h2 Config：
let mut my_settings = courierust::courierust_h2::settings::Settings::default();
fp.apply_to_settings(&mut my_settings);
let h2_cfg = fp.h2_config(); // client 角色的 h2::connection::Config

// 头块按伪头在前、其余小写排序的 Chrome 顺序排列：
let ordered = courierust::courierust_fingerprint::h2::order_headers_chrome(&fields);
```

指纹字段全部公开可配（`header_table_size`、`enable_push`、`max_concurrent_streams`、`initial_window_size`、`max_header_list_size`、`connection_window_update`、`sort_headers`），可以精确匹配某个 Chrome 版本。Chromium 偶尔会改这些值——请与你模拟的 Chrome 构建保持同步。

## 接入 TLS

内置客户端可以在 `ClientConfig::tls` 中配置 `RootStore`，直接请求 `https://`。如果需要自定义传输，编解码对 `courierust::courierust_io::Read` / `courierust::courierust_io::Write` 泛型化，你可以：

1. 构造 `TlsProfile`（用 Chrome 的，或你自己的）。
2. 把 ClientHello 参数交给你的 TLS 库（rustls、native-tls，或 FFI 到 OpenSSL/BoringSSL），或者使用 Courierust 内置的 TLS 1.3 connector。
3. 把产出的 `TlsStream` 包上 crate 的 io trait，再驱动 `h2::Connection` / 客户端。

HTTP/2 侧直接覆盖：连接配置用 `ChromeH2Fingerprint::h2_config()`，出站头块用 `order_headers_chrome()`。
